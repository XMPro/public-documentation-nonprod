v5.0 Release Notes

This section contains the release notes for XMPro v5.0 platform, providing information about new features, improvements, and bug fixes across all core products. Key highlights include MAGS reaching general availability in XMPro AI, the re-platforming of Subscription Manager into a modernised Subscription Manager and a new Identity Server, Kubernetes-native deployment on Azure and AWS, OpenTelemetry observability across all services, the platform upgrade to .NET 10 and Angular 21, and App Designer Connector Pooling.

Warning

Forward-only release: Once you upgrade to v5.0.0 there is no supported path back to v4.x. Test the upgrade in a non-production environment first.

Breaking changes: The following have been retired in v5.0.0. Check each one against your deployment before upgrading.

  • Ubuntu Stream Host: no longer available to download from the Collections page. See Deploy Stream Host for the remaining options.
  • XMPro Notebooks (Jupyter): disabled in v4.5.4 and now removed entirely, including its product registration and database migrations. XMPro AI is unaffected.
  • Autodesk Forge block: can no longer be added to applications, and has not worked at runtime for some time. Existing blocks stay viewable at design time. To display Autodesk models, use the Metablock Autodesk example.
  • Mosquitto: removed from the XMPro container registry, as it is not part of the product suite. A Stream Connector still requires an MQTT broker, which you now supply.
  • Swagger endpoints and the /health-ui dashboard: no longer served. The /health and /health/ping endpoints are unaffected.

Date Released: 22 Sep 2026

Common

Change Type Description
Deployment

Kubernetes-Native Deployment on Azure and AWS: XMPro v5.0 deploys to Kubernetes through a fully supported Helm chart, validated against both Azure Kubernetes Service (AKS) and Amazon Elastic Kubernetes Service (EKS). Every product deploys through that one chart, including the modernised Subscription Manager and the new Identity Server, so all of them are installed, upgraded, and monitored the same way.

A single cluster can host multiple isolated XMPro environments, each with its own databases, domain, TLS certificates, and secrets, so development, QA, and production can run side by side without duplicating infrastructure. Certificate issuance, secrets management, and database migration are handled as part of the deployment.

Terraform modules for Azure and AWS are provided as unsupported reference templates for standing up the underlying cloud infrastructure. Provisioning your cloud infrastructure and administering your Kubernetes cluster remain your responsibility.

The Windows Server installer is not available in v5.0.0. Subscription Manager, Identity Server, App Designer, Data Stream Designer, and XMPro AI deploy through Docker or Kubernetes only. Stream Host is unaffected and remains supported on Windows, as either a Console application or a Windows Service.

Existing App Service and legacy deployments are unaffected until you migrate. If you run the web products on Windows Server today, plan your migration before upgrading. See Deploy XMPro, and the Azure and AWS migration articles.
Feature

Subscription Manager re-platformed and split into two components: Subscription Manager has been rebuilt as a modernised, containerised application, and the identity provider it previously contained is now a standalone Identity Server, path-routed at /identity.

Separating the two means authentication can be scaled, monitored, and patched independently of subscription management, and it removes the legacy hosting stack that tied Subscription Manager to Windows.

Existing App Designer, Data Stream Designer, and XMPro AI installations remain fully compatible and no application-level changes are required on your side.
Feature

Observability and OpenTelemetry: XMPro products now export telemetry using OpenTelemetry, the vendor-neutral standard for traces, metrics, and structured logs. All six services (App Designer, Data Stream Designer, Subscription Manager, Identity Server, XMPro AI, and Stream Host) emit telemetry over the OpenTelemetry Protocol (OTLP) to an endpoint you provide, whether an OpenTelemetry Collector you run or a vendor service that accepts OTLP directly.

This means XMPro telemetry can be routed to the observability backend your organisation already operates, such as Grafana, Datadog, Splunk, or Azure Monitor, rather than being tied to a single platform. Export is opt-in and disabled by default; no telemetry leaves your deployment until you configure an endpoint.

For Azure Kubernetes deployments, OpenTelemetry runs alongside existing Application Insights monitoring as an additional export path. For AWS Kubernetes deployments, where Azure-native monitoring is not available, it provides the primary observability channel.
Security

Product security and stability: This release consolidates a large body of security work across the platform:

  • Supported .NET runtime: App Designer, Data Stream Designer, Stream Host, XMPro AI, and Subscription Manager now run on .NET 10, together with their container base images and build pipelines. .NET 10 is supported until November 2028, whereas .NET 8 reaches end of support in November 2026, so the platform stays on a runtime that continues to receive security patches. Feature parity is preserved and the Subscription Manager legacy stack is unchanged.
  • Supported Angular framework: The App Designer, Data Stream Designer, Subscription Manager, and XMPro AI interfaces moved from Angular 15, which is out of support, to Angular 21, along with major dependencies including DevExtreme, Monaco Editor, and JSPlumb. This restores security patch coverage for those four interfaces and cleared a large set of dependency findings that could not be resolved on the older framework. Existing functionality and supported browsers are unchanged. The Identity Server sign-in interface remains on Angular 5 and is scheduled for replacement rather than an in-place upgrade; its four outstanding dependency findings (three in @angular/common, one in uuid) have been assessed as not exploitable in XMPro's usage.
  • Dependency remediation: Software composition analysis findings were cleared across App Designer, Data Stream Designer, XMPro AI, Subscription Manager, and Identity Server. Packages upgraded or pinned include ws, fast-uri, brace-expansion, lodash, jsrsasign, and HtmlSanitizer. Unused direct dependencies were removed rather than patched where they were not needed at all.
  • Slimmer container images: curl and its dependency chain were removed from the Debian-based Stream Host and xmpro-run base images, as they were not used at runtime, and the licenses container was moved off Ubuntu 16.04. Both changes eliminate whole classes of vulnerability finding at source rather than suppressing them.
  • Reduced attack surface: Swagger endpoints and the /health-ui dashboard are no longer served, and the redundant SecureText setting type has been removed in favour of explicit interface masking for plain text secrets. See the breaking changes at the top of this page.
  • Penetration test findings: three findings against App Designer were remediated.
    • Ticket ID17586, medium severity, CVSS v4.0 score 6.9: the application, connector, and variable metadata endpoints, which describe an application's internal structure, could be read by unauthenticated users. Authentication is now enforced on those endpoints.
    • Ticket ID17589, low severity, CVSS v4.0 score 2.7: content entered into fields such as Notes was stored and later rendered without sufficient sanitisation, so a crafted element with inline styles and an external link could render as a convincing security notice. Input validation and context-aware output encoding are now applied.
    • Ticket ID17949, low severity, CVSS v4.0 score 2.3: adding a single quote to a request parameter returned an HTTP 500 response carrying validation detail and trace identifiers, which could be used to inflate log volume and obscure other activity. Invalid input is now rejected as a validation failure.
  • Deprecated Azure AD Graph API: Ticket ID17325 Subscription Manager's remaining calls to the deprecated Azure AD Graph API now target Microsoft Graph. The calls caused no functional problem, but infrastructure teams were being notified that an application was using deprecated APIs.
  • Transport and header hardening: minTlsCipherSuite is now applied through Terraform for all App Service deployments, with a documented manual procedure for deployments not managed by Terraform, and Cross-Origin Embedder Policy and Cross-Origin Resource Policy headers are supported without breaking the Identity Server OIDC iframe flow.
  • CWE-522: The Linux database migration container entrypoints traced their fully expanded command line to standard output, disclosing the SQL administrator password, the company and site administrator passwords, all product keys, and the collection secret in plain text to anyone able to read container logs. The shell trace has been removed. This affects released versions from v4.5.4 onward, so treat any credentials that appeared in the logs of an existing deployment as exposed and rotate them.

App Designer

Change Type Description
Feature

Connector Pooling: Connector Pooling reuses Connector handler instances across the environment to improve Application load performance.

Frequently used Connectors are served from the pool as a warm load rather than being recreated on each request, reducing load times for pages with multiple Connectors. The pool evicts the least recently used handler to stay within a configurable size limit, keeping memory usage predictable, and saving or deleting a Connection evicts its pooled handler so configuration changes take effect without any manual step.

Together with a recent connector-side change that resolves the current user from the request token instead of calling App Designer's user-info endpoint on every read, this raises the fast-query connector ceiling from roughly 30 to over 250 concurrent users, and changes the behaviour beyond that ceiling from errors for every user to graceful degradation. The connector-side change ships separately in the Azure SQL Connector and SQL Server Connector v2.29+, so upgrade those Connectors to see the full benefit.

Company administrators can observe and manage their own company's entries from the App Designer Settings page, using the Connector Pool Report, the Live Connector Pool Report, and the Clear Pool action. The maximum pool size is set at deployment time, see Connector Pool configuration for the Helm, environment variable and Terraform options.
Enhancement

Ticket ID17887 Esri Map OAuth 2.0 support: The Esri Map block now supports App Authentication (OAuth 2.0) as an alternative to API Key authentication.

The block authenticates with ArcGIS as a registered OAuth 2.0 application using the client credentials grant, with access tokens refreshed automatically so no user sign-in is required. Client credentials are stored as XMPro Variables, with the Client Secret encrypted so that it is resolved server-side only and never exposed to the browser.

This gives you application-scoped, rotatable credentials in place of a shared long-lived API key, and supports both ArcGIS Online and ArcGIS Enterprise (on-premises) portals. Existing API Key configurations continue to work unchanged, and API Key remains the default Authentication Mode.
Enhancement Tree Grid Recursive Selection: A new Recursive Selection property has been added under Behavior on the Tree Grid block, visible only when Allow multiple select is enabled. When enabled, selecting a parent row automatically selects all of its children, and deselecting one child leaves the parent partially selected. It defaults to False, matching the previous behaviour, so existing applications are unaffected until you opt in.
Enhancement Ticket ID16144 Expressions Read Data from Any Ancestor Component: Components in App Designer can be deeply nested, for example a chart inside a tab inside a container inside a page. Expressions now support multi-level parent references such as {Parent.Parent.fieldName} and deeper, traversing up the component hierarchy within a safe depth limit and failing gracefully rather than returning empty values. Reading from multiple sibling parents shipped in v4.5.0; this adds deep chain traversal. Existing single-level {Parent.fieldName} expressions are unchanged.
Fix Ticket ID15733 Connector Logs: Opening the connector logs showed nothing even though log records existed in the database, and one connection's error was reported as a new error against every connection using the same connector.
Connector logs now display correctly, the logs icon appears only for connections that have logs, and error indicators apply only to the connection that produced the error.
Fix Ticket ID16713 Boolean Data Grid Column Validation: A Boolean column backed by a required database column could be saved without a value. The save then failed with a database error, and the connector logs showed an attempted null insert.
The checkbox editor's third, indeterminate state produced a null value, and the standard required-field validation did not treat null as missing for Boolean columns. Boolean columns now use validation that rejects null while still accepting false, so the constraint is caught in the interface rather than by the database.
Fix Ticket ID16753 Expression Replace Function: The Replace function replaced only the first occurrence found in the string, so Replace("aabc abcd abcde abcdef","abc","") did not return a d de def.
Replace now applies to every matching occurrence in the given text.
Fix Ticket ID16754 Application Import File Name: During an application import, the top of the selected file name was clipped and could not be read in full.
The selected file name now displays in full.
Fix Ticket ID16936 Editing an Application from the Applications Blade: Selecting Edit from the Applications blade opened an older version, while selecting Edit on the application card correctly opened the latest version.
Both entry points now open the latest version.
Fix Recommendation Version Title Truncation: A recommendation version title appeared truncated when that version was selected in the version list.
Titles now display in full. This extends the recommendation version handling corrected for Ticket ID16939 in v4.5.4.
Fix Ticket ID17625 Large Connector Upload: Uploading a large connector returned ERR_INPUT_VALIDATION_MAXIMUM_LENGTH, and files that had uploaded successfully on earlier versions were rejected, blocking connector version updates.
The upload endpoint enforced an input length limit smaller than the connector payloads being uploaded, and it was not configurable. The limit has been raised and made configurable.
Fix Ticket ID17666 SQL Connector with Windows Authentication: With Use SQL Authentication cleared, the SQL Connector caused App Designer to log "Cannot load library libgssapi_krb5.so.2" and then restart.
The App Designer container image did not include the Kerberos library that the driver loads for integrated authentication. The library is now present, so the SQL Connector works with both authentication modes.
Fix Ticket ID17459 Live Data Updates Across a Filter Boundary: Where a data grid filtered on a field, a record whose value changed so that it no longer matched the filter stayed in the view, and a record that changed so that it now matched did not appear.
Live data changes were filtered against each subscription's filter before being sent, and because a Connector publishes only the new values there was no way to know that a record had previously matched. Updates that could cross a filter boundary are now sent regardless of the subscription filter, and the client converts them into an insert or a removal as appropriate.
Fix Ticket ID14579 Application File Upload Size: Uploading an application file above roughly 30 MB failed silently or with a generic error, even though the configuration allowed 200 MB. A 150 MB application containing Unity models could not be uploaded.
The upload endpoint was missing the request size limit that the other upload endpoints already carried, so it fell back to the framework default. The limit has been added, bringing application file uploads in line with connector uploads and application import.
Fix Ticket ID17911 Validation Group Persistence: The validation group selected on a button was not retained when the block's properties were reopened, so the validation configuration had to be reapplied.
The selected validation group now persists. The related problem of the button itself not responding was corrected in v4.6.
Fix Recommendation Alert Manager Column Filters: Selecting a column filter, choosing Select All, then clearing some options and confirming produced an error.
Clearing items in a multi-select grid filter now applies without error, and the results correctly exclude the cleared items.
Fix HTML Tags in Recommendation Connector Data: When a data grid was bound to the recommendation connector's Alerts or Alerts With Data entities, the Title, Description, ActionDescription, and Comments columns contained raw HTML tags.
Those columns now return their text content without HTML tags.
Fix Alert Notes Updated by the Update Recommendation Agent: Where an alert's Comments field was updated by the Update Recommendation agent while the alert was open, the user was prompted that a change had occurred, but accepting it left the notes field unchanged.
Values written by the agent contain no HTML tags, so the rich text editor wrapped the value and marked the local copy as modified; on accepting the incoming change it reapplied the same edit before the new values arrived, and the modified flag suppressed the update. The editor no longer alters the value while incoming values are being retrieved.
Fix Ticket ID14904 Recommendation Analytics Block Labels and Fonts: The Recommendation Analytics block used fixed, oversized fonts for its values, its heading wrapped across the Period and Alert ranking selections, and the identifier used for filtering was not shown.
Font sizes are now consistent across the block's values, the heading sits below the Period and Alert ranking selections, and the identifier used for filtering is shown.
Fix Typed Dates with a Single-Digit Day: Typing a non-padded date whose day is 1, 2, or 3 into a form Datebox changed the value: 8/3/2026 committed as 8/2/2026. The altered value was the one that saved.
The date mask does not advance to the next section on a typed separator while a single-digit day could still become a valid two-digit day, so the first digit of the year merged into the day. An explicit zero-padded display format is now applied. Zero-padded entry and calendar selection were never affected.
Documentation Ticket ID16979 Native Date Picker Format: With Picker Type set to Native, the Date Selector ignored the browser locale and defaulted to dd/MM/yyyy for English, while applying the expected format for other languages.
This is the documented behaviour of the underlying control, which uses the device locale when the picker type is native, so it cannot be changed in XMPro code. The Date Selector documentation now states that the native option uses the device's local settings, while the default and calendar options follow the browser's display language. Set Picker Type to Default or Calendar if you need browser-locale formatting.

Change Type Description

XMPro AI

Change Type Description
Feature

MAGS reaches General Availability: MAGS (Multi-Agent Generative Systems) is the multi-agent capability within the XMPro AI product, and reaches general availability in this release. The capability has been delivered for some time through applications built in App Designer; from v5.0 onwards it moves into XMPro AI.

MAGS is built around ORPA (Observe, Reflect, Plan, Act), a cognitive framework that lets an agent reason more like a domain expert than a workflow script: agents weigh the strength of their own evidence, flag when they are uncertain, and recall relevant past situations before acting, rather than following a fixed decision tree. Two areas are delivered in v5.0.0:

  • MAGS Configuration: define the agent teams that do the work, along with the profiles, tools, actions, measures, and policy constraints they draw on. A guided wizard walks you through creating a team.
  • Agent RAG: build and manage the retrieval collections that give agents their grounding, covering documents, embedding models, and chunking strategies, with a dashboard and quality testing to check what an agent will actually retrieve.

For you this means agent behaviour is configured and governed in one place as part of a product, rather than assembled inside individual applications.

Package Manager

Change Type Description
Fix Nested and Duplicate Settings Translations: When packaging certain agents, some settings and options were left untranslated. This affected agents with two dropdowns sharing identical options in the same group, a token box whose key matched its group's caption, and dropdowns whose options shared display values.
Four defects were found in the translation logic: the duplicate-skip counter reset on each recursive call; batching at ten items reset the duplicate tracking, so items after a batch boundary lost their disambiguating suffix; the property search matched on any property rather than the one used to generate the translation key; and option keys were generated without parent context. All four are corrected, and existing packaged agents are unaffected.
