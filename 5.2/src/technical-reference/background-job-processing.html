Background Job Processing

Note

For Kubernetes deployments, these defaults are pre-configured and can be overridden via Helm values or environment variables.

Overview

XMPro uses HangFire to process background jobs for email notifications and system maintenance tasks. HangFire automatically handles job scheduling, retry logic, and execution across multiple server instances.

This feature is only available in App Designer (AD). Data Stream Designer (DS) and Subscription Manager (SM) do not use HangFire for background job processing.

Configuration Variables

These settings are pre-configured in appsettings.json and can be overridden via environment variables or Azure App Service settings:

Variable Default Description
HangFire:WorkerCount 5 Number of concurrent background workers (HangFire default is 20)
HangFire:SchedulePollingIntervalSeconds 15 How often to check for scheduled jobs
HangFire:ServerCheckIntervalSeconds 60 Server heartbeat interval
HangFire:QueuePollIntervalSeconds 15 Queue polling frequency
HangFire:SlidingInvisibilityTimeoutMinutes 5 Job visibility timeout
HangFire:UseRecommendedIsolationLevel true Use optimized SQL isolation level
HangFire:DisableGlobalLocks true Disable global locks for better performance
HangFire:EnableDashboard false Enable/disable HangFire dashboard at /hangfire endpoint.
Warning: Intended for Dev/QA environments only. The dashboard exposes job history, server status, and retry controls. Production use requires configuring an authorization policy to restrict access.

Customizing Configuration

Via Helm Values (Kubernetes)

# Add to your values.yaml or use --set flags
ad:
  env:
    HangFire__WorkerCount: "10"
    HangFire__SchedulePollingIntervalSeconds: "30"

Via Environment Variables

# For local development or manual deployment
export HangFire__WorkerCount=10
export HangFire__SchedulePollingIntervalSeconds=30
Note

Double underscore (__) is used in environment variable names to represent the colon (:) in configuration paths. This is standard .NET configuration convention.

When to Customize

The default settings are optimized for most deployments. Consider adjusting if:

  • High job volume: Increase WorkerCount (but monitor database connections)
  • Idle systems: Increase polling intervals to further reduce database load
  • Real-time requirements: Decrease SchedulePollingIntervalSeconds for faster job execution
Tip

Monitor your database query metrics before and after changes to verify the impact.
