Security Advisory: eMudhra Intermediate CA Compromise

Published: 22 October 2026 Severity: High

Summary

On 17 October 2026, a security researcher found that eight intermediate certificate authority (CA) certificates issued by eMudhra, sold under the emSign brand, had private keys small enough to be recovered trivially. Anyone holding these keys can create a certificate for any website or service, and software that still trusts the eMudhra root certificates will accept it.

Chrome, Firefox, Safari and Windows blocked the affected certificates between 17 and 20 October 2026. No attacks using them have been reported.

XMPro's own certificates were not issued by eMudhra and do not need to be replaced. The issue affects outbound connections made from XMPro containers, because the container images include the standard Linux list of trusted root certificates, and that list includes the eMudhra roots. To exploit this, an attacker would need to be able to intercept network traffic between an XMPro container and a service it connects to.

Affected Deployments

Container deployments

Every XMPro container image released before the fixed versions below trusts the compromised certificates. This applies to all 4.x release lines, including versions older than 4.4, and covers the App Designer, Data Stream Designer, XMPro AI, Stream Host and database migration images on Docker, Kubernetes, AKS and EKS.

We recommend upgrading to the latest XMPro version at your convenience. If you need to stay on your current release line, upgrade to the fixed version for that line.

Release line Affected versions Fixed version
4.4 4.4.23 and earlier 4.4.24
4.5 4.5.5 and earlier 4.5.6
4.6 4.6.1 and earlier 4.7.0
4.7 None released 4.7.0

The 4.6 fix ships in 4.7.0, which continues the 4.6 line. There is no separate 4.6.2 release.

Releases older than 4.4 do not receive this fix. Upgrade to one of the fixed versions above.

Windows installer deployments

Windows installations of XMPro use the Windows certificate store, so no XMPro update is required. Microsoft blocks the affected certificates through its automatic root certificate updates. Servers that receive Windows updates are already protected.

Servers that are offline, or where automatic root certificate updates are turned off by group policy, do not receive this automatically. Apply Microsoft's updated untrusted certificate list to those servers through your normal offline patching process.

What the Fixed Versions Change

  • Every XMPro container image stops trusting all eMudhra and emSign root certificates, including the path through the AAA Certificate Services cross-signature. The image build fails if any of these roots remain or if any of the compromised certificate chains still verifies.
  • In the Stream Host Python images, Python HTTP libraries such as requests, httpx and boto3 use the same system list of trusted certificates, rather than a separate copy bundled with Python.

After upgrading, XMPro containers will no longer connect to services whose certificates are issued by eMudhra or emSign. If you rely on such a service, contact XMPro Support before upgrading.

Recommended Actions

  1. Container deployments: Upgrade to the latest XMPro version at your convenience, or to the fixed version for your release line.
  2. Windows installer deployments: Confirm that your XMPro servers receive Microsoft's root certificate updates, or apply them manually if the servers are offline.
  3. Custom trusted certificates: Stream Host containers trust any certificate mounted into /trustedcerts. Make sure no eMudhra or emSign certificate is mounted there, because it would be trusted again.
