v4.7 Release Notes

This section contains the release notes for XMPro v4.7 and the v4.6 releases it continues, providing information about new features, improvements, and bug fixes across all core products. Key highlights in v4.7.0 include App Designer connector pooling, server-side sort and filter for the Data Grid, and delivery of deployment assets from XMPro GitHub Enterprise. Key highlights in v4.6 include the Streams as Connectors architecture, Stream Host Event-Level Streaming architecture, OAuth SMTP support, and security enhancements across all products.

v4.7.0

Date Released: TBC

v4.7.0 continues the v4.6 line. It includes every change from v4.6.1 and the changes prepared for v4.6.2, which was not released separately. If you are upgrading from v4.6.0, also read the v4.6.1 notes below.

Common

Change Type Description
Deployment

Deployment assets delivered from XMPro GitHub Enterprise: From v4.7.0, XMPro delivers deployment assets from XMPro GitHub Enterprise instead of public GitHub.

  • The Terraform module for Azure App Service and Azure Container Instances (infra-azureac) is synced one way into a private repository that you host. Only content marked final for a release is synced.
  • XMPro container images are no longer pulled from a public XMPro registry. XMPro pushes the release images into a container registry that you host. Set acr_url_product to that registry.

The deployment flow and scripts are unchanged. The Subscription Manager package is still downloaded from download.app.xmpro.com.
Deployment

Terraform module changes:

  • When use_existing_database = true, the Subscription Manager database migration uses the existing database's product IDs and keys instead of the evaluation values. Two new inputs, existing_xmpro_notebook_product_id and existing_xmpro_notebook_product_key, supply the XMPro Notebook pair.
  • The migration4.4 example can reuse an existing SQL server (use_existing_database, existing_sql_server_fqdn) and can add extra CNAME and NS records to the custom DNS zone (additional_dns_cname_records, additional_dns_ns_records).
  • The App Designer connector pool cap uses its default of 128. The Terraform module does not expose it in this release. See Connector Pool Configuration.

App Designer

Change Type Description
Enhancement

Connector pooling: App Designer now keeps a pool of loaded Connector handlers and reuses them across requests, instead of loading the Connector for every request. Pages that read from Connectors load faster, and App Designer handles more concurrent users.

  • Each App Designer instance keeps its own pool, capped at 128 by default. When it is full, the least recently used connection is evicted first. See Connector Pool Configuration.
  • Saving or deleting a Connection evicts its pooled handlers on the App Designer instance that handled the save. Other instances are not notified. Live Connector subscriptions that are already open keep running until their last subscriber disconnects.
  • Two new reports on the Settings page, Connector Pool Report and Live Connector Pool Report, show what is in each pool. See Manage Site Settings.
  • A Company Admin can clear their company's pooled handlers with the Connector Pool action in the Behavior category of the Settings page. The action applies to the App Designer instance that handles the request.
  • Live connectors are now closed cleanly when App Designer shuts down.
Enhancement

Server-side sort and filter for the Data Grid: A new Enable Remote Sort/Filter setting on the Data Grid block sends sort, filter and grouping to the Connector along with paging, instead of fetching the full dataset when a user sorts or filters. The setting appears when paging is enabled and is off by default.

No current XMPro Connector handles these parameters, so turning the setting on stops sorting and filtering until the Connector is updated to support them.

With Enable Remote Sort/Filter on, a Filter set in the designer combines with a user's column filter instead of being replaced by it. The Data Grid also gets an Allow Sorting setting, which can be bound to a variable.
Enhancement

Encrypted Power BI Application Secret: The Application Secret on the Power BI block is now stored encrypted, and the secret box stays blank after saving. When Use Variables is on, only secure variables can be selected for the secret.

The secret is decrypted on the server and is never returned to the browser.
Change

Power BI blocks in Application mode load: Pages that contain a Power BI block in Application authentication mode now get relaxed Cross-Origin-Opener-Policy and Cross-Origin-Embedder-Policy headers, so the Power BI sign-in completes and the report displays. All other pages keep the default headers.

Browsers apply these headers to the whole page load, so pages opened by in-app navigation after a Power BI page keep the relaxed headers until the next full page load.
Change

Accepted image formats: Icon and thumbnail uploads for apps, widgets, categories, recommendation rules, templates and the block Icon property accept PNG, JPEG, GIF, BMP and WebP. Other formats, including TIFF, are rejected.

  • A rejected upload shows no message, and the New App form keeps Save disabled until a supported image is uploaded.
  • A template whose existing thumbnail is a TIFF can't be saved until the thumbnail is replaced.
  • The Image block is not affected.
Fix Nested Parent expressions rendered blank: Expression bindings using Parent.Parent or deeper rendered blank when the chain reached the top-level data container.
Nested Parent fields now resolve at every level.
Fix Power BI block blank in Application mode: A Power BI block using Application authentication mode stayed blank after the embed token was retrieved.
The block now renders the report.
Fix App Designer restart under database load: When the database timed out while App Designer was recording a Connector error, App Designer could stop and restart.
The error is now logged and App Designer keeps running.
Fix Office address in emails: Email templates now show the current XMPro office address.

v4.6.0

Date Released: 13 Mar 2026

Common

Change Type Description
Feature

Streams as Connectors: New architecture that allows App Designer applications to use a published Data Stream as a data source.

The XMPro Stream Connector is used in App Designer to connect to a published Data Stream, supporting read, insert, update, and delete operations. The backing Data Stream comprises a XMPro Stream Listener, a Connector Agent (new category), and a XMPro Stream Action Agent. Agent configuration values are passed directly into the connected stream at runtime by App Designer. With Connectors now available in both App Designer and Data Stream Designer, attempting to import an integration file (.xmp) into the wrong product returns a clear error identifying which product the file belongs to.

Using this new feature results in more resilient App Page page loads and less infrastructure to run the XMPro platform, but does require a MQTT broker to use it.

If you are upgrading, a migration script is available to transition your existing connections. Contact your XMPro account manager for assistance.
Enhancement

OAuth SMTP Configuration Support: Platform administrators can now configure OAuth 2.0 authentication for XMPro's outbound email notifications instead of username and password credentials.

OAuth SMTP authentication is supported across all deployment methods, including the Windows Server installer, Terraform modules, and Docker (xmpro-run). Administrators can configure the OAuth client ID, client secret, and token endpoint to match their email provider's requirements.

Modern email providers such as Microsoft 365 and Google Workspace are phasing out basic authentication for SMTP. OAuth support ensures XMPro's email notifications, including recommendation alerts, user invitations, and system notifications, remain fully operational in environments where basic auth has been disabled, while improving the overall security posture of your deployment.
Deployment

Azure Container Instance Enhancements: Two improvements to Stream Host deployments using Azure Container Instances (ACI):

  • Virtual Network Integration: ACI deployments can now be connected to an Azure Virtual Network, enabling private networking without public-facing container endpoints and meeting enterprise security and compliance requirements.
  • Right-Sized Default Configuration: Default CPU and memory allocations have been updated to better reflect production workload requirements, reducing the need for manual configuration adjustments after initial deployment.
Security

Product security and stability: We've addressed several security vulnerabilities in this release:

  • CVE-2022-26907: Upgraded Microsoft.Rest.ClientRuntime from 2.3.20 to 2.3.24 in App Designer and from 2.3.11 to 2.3.24 in Data Stream Designer.
  • CVE-2022-34716: Upgraded System.Security.Cryptography.Xml from 4.4.2 to 6.0.1 in App Designer.
  • CVE-2023-29331: Added System.Security.Cryptography.Pkcs 6.0.3 to App Designer.
  • CVE-2025-54575: Upgraded SixLabors.ImageSharp from 3.1.7 to 3.1.11 in App Designer and Data Stream Designer.
  • GHSA-4vgm-c2wm-63mw: Upgraded Microsoft.AspNetCore.App.Runtime.linux-musl-x64 from 8.0.24 to 8.0.25 in Subscription Manager, App Designer, Data Stream Designer, and XMPro AI.
  • Removed unused npm dependencies and overrode transitive package versions in App Designer to resolve Veracode-identified vulnerabilities in tar and tsiclient.npm.
  • CWE-117: Applied log output sanitization to neutralize CRLF injection in App Designer and Data Stream Designer.
  • CWE-285: Added class-level [Authorize] attributes in App Designer and Data Stream Designer to enforce authentication by default, with explicit [AllowAnonymous] exemptions for public endpoints such as error pages and silent token renewal.

Stream Host

Change Type Description
Feature

This release introduces a set of improvements that together deliver a more reliable, efficient, and upgrade-friendly Stream Host:

  • Memory Optimisation: Rearchitected with Event-Level Streaming Architecture, processing data one event at a time through a chain of agents rather than accumulating large in-memory batches.
    • Each agent releases memory as soon as it forwards an event, preventing unnecessary retention of intermediate results and significantly reducing RAM usage.
    • Downstream agents begin processing immediately upon receiving each event, without waiting for the full batch from the preceding agent.
    • Supports both event-level and batch processing: Event-Level Streaming for agents that can process each event independently and Agent-Level Streaming retained for agents that require full datasets (e.g. time-series for model-based analysis).
  • Backward Compatibility: Event-Level Streaming-enabled agents can run on pre 4.6 Stream Host instances, enabling rolling upgrades without downtime, but they will revert to Agent-Level Streaming behavior.
  • Process Isolation: Errors in a data stream are contained and no longer affect other streams running on the same Stream Host instance.
  • Stable Assembly Versions: Agent DLLs now maintain a consistent assembly version across builds, so developers no longer need to recompile custom agents after a Stream Host update.

Process isolation and some memory improvements apply immediately without any changes to existing agents. To take full advantage of Event-Level Streaming, agents must be updated to implement the new async methods and overloads - see XMPro.IOT.Framework under NuGet Packages below.

XMPro.IOT.Framework
Change Type Description
Enhancement

The following async methods and constructor overloads were added to existing interfaces and args classes to support Event-Level Streaming feature - see Stream Hosts above:

  • IPollingAgent: new PollAsync() overload for async polling.
  • IReceivingAgent: new ReceiveAsync(string, IAsyncEnumerable<byte[]>) overload for continuous stream ingestion.
  • IMapAndReceiveAgent: new ReceiveAsync(string, IAsyncEnumerable<(byte[], byte[])>) overload for Agents that receive a mapped/typed stream of data evenets.
  • OnPublishArgs: new constructors accepting IAsyncEnumerable<byte[]> and IAsyncEnumerable<string> for streaming event publishing.
  • OnErrorArgs: new constructor accepting IEnumerable<JToken> for streaming error data.

Agents that do not implement the async methods and overloads continue to work without any changes.
